# WebSocket protocol

Endpoint: `/ws` (same origin as the app; `wss://` in production). One connection per tab/device.

## Envelope

Every frame, in both directions, is one JSON object:

```json
{ "id": "6b0f…", "type": "message.send", "ts": 1760000000000, "from": "user-uuid (server→client only)", "payload": { } }
```

| Field | Client → server | Server → client |
|---|---|---|
| `id` | Request id chosen by the client (8–64 chars, usually a UUID). Used for the ack and for duplicate detection. | Event id generated by the server. The **same** fact delivered to several of a user's devices carries the same id. Clients drop ids they've already seen. |
| `type` | Request type (below). | Event type (below), or `ack` / `auth.ok`. |
| `ts` | Client clock, informational. | Server time (ms). |
| `from` | — ignored if sent | The user who caused the event, set by the server from the authenticated connection. |
| `payload` | Request data. User/sender ids in payloads are never trusted. | Event data. |

## Connection lifecycle

```
connect /ws ──► first frame MUST be {"type":"auth","payload":{"access_token":"…"}} within 10 s
            ◄── {"type":"auth.ok","payload":{"conn_id","user_id","device_id","protocol":1,"server_time","heartbeat_interval_ms"}}
            ──► (client) sync.head / sync … until caught up
            ──► presence.subscribe, flush outbox, call.resume (if in a call)
```

* The token travels in the first frame, never in the URL (URLs end up in proxy logs).
* The connection is registered (and starts receiving live events) **before** `auth.ok` is sent, so anything committed
  while the client syncs arrives as a live event (see [SYNC.md](SYNC.md)).
* Browsers must send an allowed `Origin` (`CORS_ORIGINS`); other origins are refused with HTTP 403 (cross-site WebSocket hijacking).
* Connection attempts are limited per IP (HTTP 429) and live connections per user.

### Close codes

| Code | Meaning | Client action |
|---|---|---|
| 4001 | Auth timeout | Reconnect |
| 4002 | Auth failed (bad/expired token) | Refresh the token, then reconnect |
| 4003 | Session revoked (logout, password change, token theft) | Go to login; don't reconnect |
| 4004 | Protocol error (bad JSON/envelope) | Fix client |
| 4008 | Too many connections | Back off |
| 1009 | Frame too large (> 64 KB) | — |
| 1012 | Server restarting | Reconnect with backoff |

### Heartbeat & dead connections

* Server: sends a WebSocket ping every `HEARTBEAT_INTERVAL_MS` (25 s); a connection that hasn't answered the previous ping is terminated.
* Client: browsers can't see protocol pings, so the client sends `ping` every 20 s and treats a missing ack within 8 s as a dead
  connection (e.g. after a Wi-Fi → mobile-data switch where TCP dies silently). It abandons the socket and reconnects immediately.
* Reconnects use exponential backoff with jitter (0.5 s → 30 s), reset after 10 s of stable connection, and retry immediately on the
  browser `online` event or when the tab becomes visible.

## Requests and acks

Each request gets exactly one ack:

```json
{ "type": "ack", "payload": { "ref": "<request id>", "ok": true, "result": { } } }
{ "type": "ack", "payload": { "ref": "<request id>", "ok": false, "error": { "code": "not_found", "message": "Conversation not found" } } }
```

* **No ack = unknown outcome.** Clients must not treat `WebSocket.send()` as success; they time out and retry.
* **Duplicate requests.** For state-changing requests the server stores each ack for 5 minutes under `(user, request id)`. A repeated id
  gets the original ack replayed instead of being processed again. A repeat that arrives while the original is still running gets
  `error.code = "in_progress"` (retry shortly).
* Message sends are additionally idempotent on `client_msg_id` forever (database unique key), so resending after a reconnect, or via
  REST, never creates a duplicate.
* Error codes match the REST API, plus `unknown_event`, `in_progress`, `invalid_call_state`, `call_on_other_device`, `resume_required`, `peer_unavailable`.
* Per-connection rate limit: 300 frames / 10 s (`rate_limited` ack).

## Client → server requests

| type | payload | result |
|---|---|---|
| `ping` | `{}` | `{ server_time }` |
| `sync.head` | `{}` | `{ cursor }` |
| `sync` | `{ cursor }` | sync batch (see API.md › Sync) |
| `message.send` | `{ conversation_id, client_msg_id, type: "text", body, reply_to_id? }` | `{ message, duplicate }` |
| `message.delivered` | `{ message_ids: [...≤500] }` | `{ updated }` |
| `message.delivered_all` | `{}` | `{ updated }` |
| `message.read` | `{ conversation_id, up_to_seq }` | `{ updated }` |
| `message.delete` | `{ message_id, scope: "me" \| "everyone" }` | `{ ok }` |
| `typing.start` / `typing.stop` | `{ conversation_id }` | `null` |
| `presence.subscribe` | `{ user_ids: [...≤500] }` (replaces the previous set) | `{ presence: [{ user_id, online, last_seen }] }` |
| `call.initiate` | `{ callee_id, type: "voice" }` | `{ call, busy, ice_servers }` |
| `call.offer` | `{ call_id, sdp }` | `{ ok }` |
| `call.answer` | `{ call_id, sdp }` | `{ ok }` |
| `call.ice_candidate` | `{ call_id, candidate: { candidate, sdpMid, sdpMLineIndex, usernameFragment } }` | `{ ok }` |
| `call.accept` | `{ call_id }` | `{ call, offer, candidates, ice_servers }` |
| `call.reject` | `{ call_id }` | `{ call }` |
| `call.end` | `{ call_id }` | `{ call }` |
| `call.state` | `{ call_id, state: "connected" \| "reconnecting" }` | `{ call }` |
| `call.fail` | `{ call_id, reason: "ice_failed" … }` | `{ call }` |
| `call.resume` | `{ call_id }` | `{ call, role, ice_servers }` |

## Server → client events

| type | payload | Notes |
|---|---|---|
| `message.new` | `MessageDto` | To recipients and the sender's *other* connections. Clients ack delivery with `message.delivered`. |
| `message.status` | `{ conversation_id, user_id, status: "delivered"\|"read", message_ids, at }` | To the sender. Status only moves forward. |
| `message.deleted` | `{ conversation_id, message_id }` | Deleted for everyone. |
| `message.hidden` | `{ conversation_id, message_id }` | Deleted for me (to my other devices). |
| `conversation.read` | `{ conversation_id, last_read_seq }` | My other devices clear unread badges. |
| `user.typing` / `user.stopped_typing` | `{ conversation_id, user_id }` | Ephemeral, never stored. Clients expire "typing" after 6 s without a refresh. (These are the `USER_TYPING` / `USER_STOPPED_TYPING` events.) |
| `presence` | `{ user_id, online: bool\|null, last_seen: iso\|null }` | Only to connections that subscribed to that user, filtered by the user's privacy (`null` = hidden). |
| `status.updated` | `{ user_id }` | Someone in your feed posted; refetch. No content. |
| `status.deleted` | `{ user_id, status_id }` | |
| `status.viewed` | `{ status_id, viewer_id, viewed_at }` | To the owner. |
| `call.incoming` | `{ call: CallDto, caller: profile }` | Rings every device of the callee (`CALL_OFFER` notification step). |
| `call.offer` / `call.answer` | `{ call_id, sdp }` | Only to the peer's bound connection. |
| `call.ice_candidate` | `{ call_id, candidate }` | Only to the peer's bound connection. |
| `call.accepted` | `CallDto` | To the caller (`CALL_ACCEPT`). |
| `call.answered_elsewhere` | `{ call_id }` | Stop ringing on the callee's other devices. |
| `call.state` | `{ call_id, status, user_id }` | Peer reported CONNECTED / RECONNECTING. |
| `call.peer_disconnected` / `call.peer_resumed` | `{ call_id, user_id }` | Peer's signaling connection dropped / came back. |
| `call.busy` | `{ call_id }` | `CALL_BUSY`. |
| `call.ended` | `CallDto` | Terminal state reached: ENDED / REJECTED (`CALL_REJECT`) / MISSED / FAILED (`CALL_FAILED`). Sent to all devices of both parties. |
| `call.missed` | `CallDto` | `CALL_MISSED`, to the callee. |

## Example: sending a message

```
→ {"id":"a1","type":"message.send","ts":…,"payload":{"conversation_id":"c…","client_msg_id":"m…","type":"text","body":"hi"}}
← {"id":"e1","type":"ack","payload":{"ref":"a1","ok":true,"result":{"message":{…,"status":"sent"},"duplicate":false}}}
   (recipient)  ← {"id":"e2","type":"message.new","from":"<sender>","payload":{…}}
   (recipient)  → {"id":"b7","type":"message.delivered","payload":{"message_ids":["…"]}}
← {"id":"e3","type":"message.status","payload":{"status":"delivered","message_ids":["…"],…}}
```
